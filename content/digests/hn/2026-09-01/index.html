The article details C++26's new "hardening" mode for the standard library, which turns classic undefined behavior—like out-of-bounds `vector::operator[]`—into a terminating contract violation instead of silent memory corruption. The HN discussion quickly zeroed in on whether this actually replaces exceptions or solves a different problem, with strong pushback that contracts target programmer errors the caller *could* have avoided (like null dereferences), while I/O and resource exhaustion are still firmly exception territory. A significant split emerged around compile-time enforcement: some wished contracts could be checked statically (citing Ada/SPARK inspiration), while others countered that most contracts require whole-program analysis and that C++26 explicitly defines them as a runtime mechanism, even if vendors could optionally diagnose violations earlier. There was also a notable tangent questioning how "finished" C++26 really is, given that a new Bjarne-authored paper on contracts was submitted after the draft ballot—implying hardening may land in a state everyone agrees is experimental.
